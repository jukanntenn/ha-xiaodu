# RFC: 文档语料门禁：硬换行、交叉链接与词数预算

Status: implemented

[English](2026-09-07-document-corpus-gates.md) | 中文

## 问题

文档标准（[docs/AGENTS.md](../../../../docs/AGENTS.md)）声明了三条仅靠评审无法维持的不变量。散文每段一个物理行，因为硬换行的散文会隐藏一次变更究竟触及了哪些词——改一个词就会让所有折行重排——并让双语文档对更难比较；靠肉眼核实，这条规则会漂移。文档之间通过相对路径互相引用——README 指向配对契约、RFC 指向 RFC、RFC 指向技能——却没有任何机制核实这些目标或指向它们的 `#fragment` 锚点存在；改写过的标题或搬迁过的契约会静默失效，直到读者点击才暴露。常设文档还会不断堆积——重复的规则、复述的故事、重述的地图——因为没有机械兜底的散文规则被证明守不住，所以标准中"每个事实只有一个家"的规则需要一条执行前沿。HDSH 把这些门禁打包，让包括本仓库在内的消费仓库把它们当作配置而非惯例来获得。

## 决策

三个只核验的 prek 钩子共享一个包、一份配置文件（[`.hdsh/docs.manifest.json`](../../../../.hdsh/docs.manifest.json)）和一个立场：语料是配置，不是代码。包含与排除 glob 以及上限来自消费仓库的 manifest，并在装载时校验——空模式、绝对路径、`..` 段以及非正或非整数的上限在任何检查之前就被拒绝——符号链接文件按真实路径去重，冻结的 `.agents/rfcs/archived/` 树按 glob 排除。每个门禁只报告，从不重写。

### `hdsh docs wrap`（钩子 `hdsh-docs-wrap`）

`markdownWrap` 语料中的每个文件用 markdown-it-py（CommonMark 加 GFM 表格扩展）解析，任何行映射跨越多于一个源行的段落 token——包括列表和引用块内的段落——都连同文件、行号和首行片段一起报告。围栏代码、表格、标题和列表结构保持其格式，永不违规。YAML frontmatter 和 `:::` 容器分隔符在解析前被遮蔽，这样文档站的源文件不会误报；遮蔽只是原地留空行，因此报告仍指向真实行号。

### `hdsh docs links`（钩子 `hdsh-docs-links`）

链接、图片和引用式定义从 `markdownLinks` 语料中每个文件的 markdown-it-py token 流收集：每一条定义——包括被遮蔽的重复定义——都作为 token 抵达并携带其原始行，行内目标报告其书写所在的行而非所在块的首行。目标保留作者原文（解析器的 URL 规范化为恒等），因此诊断引用作者所写的内容。相对目标必须存在，指向 Markdown 目标的 `#fragment`——包括同文件锚点——必须命名一个真实的标题 slug 或真实 HTML 流中的显式 `<a id>`；代码示例和被注释掉的 HTML 里的锚点不算数。带协议的 URL、协议相对与根绝对目标，以及指向非 Markdown 目标的 fragment（`file.py#L10`）不在范围内。slug 遵循 GitHub 的算法、基于渲染后的标题文本计算，因此标题内的链接、行内代码和强调按其渲染结果生成 slug；下划线保留，CJK 标题保留其字符，重复的 slug 获得占用集合式的 `-1`、`-2` 后缀，匹配区分大小写。中文对侧遵循语料惯例：显式 `<a id>` 锚点加英文 fragment。百分号编码按渲染器解析目标的方式解码，畸形的转义保持原样，使链接被报告为断裂而不是让门禁崩溃。锚点集合按目标惰性计算并缓存，因此指向任何既有文件的链接都能核验而无需把该文件变成源文件；归档树被排除在扫描之外，但仍是有效的链接目标。

### `hdsh docs budgets`（钩子 `hdsh-docs-budgets`）

上限是 `wc -w` 计数（整个文件按空白分隔的 token 数），在 `docBudgets` 一节中按路径列出。被预算的文件若缺失则门禁失败，因此重命名不能悄悄地让预算变成孤儿；`--list` 报告当前用量而不失败。只有易堆积的常设文档才被预算——根 `AGENTS.md`、`docs/AGENTS.md`、README 文档对，以及 architecture 与 development 文档对；参考资料、RFC 和技能不设预算，因为在每一行都是事实的地方长度是正当的，由评审来治理。上限是一条会收紧的执行前沿：至少保留百分之五的余量，文档达到目标时就向下收紧，提高上限则需要在 PR 中给出显式理由。

## 验证

`tests/docs/` 钉住换行门禁的段落语义（顶层、列表和引用块散文受判定；围栏与表格从不）、frontmatter 与 `:::` 遮蔽分支、片段截断、带排除与符号链接去重的语料排序，以及 manifest 校验矩阵；渲染文本 slug 化（反引号、标点、带链接的标题、保留的下划线、CJK）、占用集合式的重复后缀、围栏、行内代码和注释内被忽略的显式锚点、同文件与跨文件 fragment 解析、大小写变体与跨文件的未命中、缺失目标被报告为目标而非锚点、被遮蔽的重复定义在其各自行上受检，以及目标保留作者原文并报告其自身行；还有 `wc -w` 计数、ok/OVER/MISS 行、缺失文件失败、`--list`、参数校验和装载期上限矩阵。pytest 在 100% 分支覆盖率门禁下运行，仓库自身的语料通过全部三个门禁。

## 备选方案

**用正则逐行扫描代替解析器。** 段落形状是解析出来的属性：列表、引用块和惰性续行都会击败行启发式，且 markdown-it-py 已是配对门禁的运行时依赖。

**在提交时重新折行的格式化器。** 核验而不生成：重排的钩子会重写变更触及的每个段落，制造差异噪音而非防止它。

**硬编码的语料模式。** 被其他仓库消费的门禁不能自带某个消费仓库的文件清单；glob 属于消费仓库的 manifest。

**只做文件级链接检查。** fragment 照样会腐烂，因为标题改写发生在从不查看入链的 PR 里；fragment 检查正是捕获这种衰退的那一半。

**中文侧用中文标题 slug。** GitHub 会为 CJK 标题生成 slug，但显式锚点加英文 fragment 还能挺过剥离非 ASCII 字符的渲染器；第二套惯例会分裂语料。

**复用配对门禁的链接机制。** `hdsh.pairing.links` 跨语言对按语义比较链接目标——它假定目标存在，回答的是另一个问题。存在性与锚点有效性需要自己的收集器。

**只靠指南和评审、不设预算门禁。** 堆积恰恰是在这种条件下发生的；值得保留的不变量就值得编码。

**对每篇文档都设预算。** 一刀切的上限惩罚的正是该长的那类文档——每一行都是事实的参考资料——并滋生逐文件的覆盖变更，训练贡献者对提额橡皮图章。

**在检查时校验上限。** manifest 中的零值是装载时就能完全检出的配置缺陷；把它作为检查时的一行报告会让坏掉的 manifest 藏在一次貌似通过的运行背后，这是仓库"错误配置大声失败"规则所禁止的。

## 影响

- 每段一行的规则在配置的语料上是机械的，因此差异精确显示变化的词，配对门禁的结构比较也保持清晰；Markdown 被暂存时 pre-commit 运行这些门禁，CI 则总是运行。
- 重命名标题或移动文档会让门禁在每个引用它的 Markdown 链接处失败，而不是让读者迷路；作者在同一变更中修复入链，正如他们已经必须为配对门禁的结构签名所做的那样。同文件锚点不再是盲区，因此保留英文 fragment 的中文页面必须暴露匹配的显式锚点。
- 向被预算的文档添加内容需要腾挪——把新增内容搬到其归属文档并留下指针，或压缩现有散文来支付——只增不删会让门禁失败。词数是粗糙的代理，经审慎接受：它无法判断质量，但迫使作者在添加内容的那一刻——正是他有上下文把内容放对位置的时候——做出搬迁决定。
