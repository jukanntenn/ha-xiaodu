# RFC: 简报驱动的最小翻译更新

Status: implemented

[English](2026-09-07-briefed-minimal-translation-updates.md) | 中文

## Problem

配对约定要求同一个 PR 把对侧一并带上，但两个诱人的默认做法都在浪费这份义务的预算。整篇重译会丢弃编辑未触及部分已评审的措辞，并重新打开已定术语；为一处两行的编辑加载整套指南语料，又恰恰是在给约定想要保持廉价的行为加税。日常 agent 工作因此在术语指导下直接一次完成有改动的翻译——但更重的协调场景（整篇翻译、双侧漂移、subagent 委派）需要一份工作集，把 diff、三方上下文、触及的术语行与约束规则放在一处，而不是靠隐含。

## Decision

`hdsh pairing brief [--apply] [<pair>...]`按需渲染这份工作集，从不运行于钩子或 CI：

- 每个失去同步的一侧按能安全对齐的最窄粒度映射：仅围栏代码块的拼接、有改动的 Markdown unit（最外层块节点；容器路径是对齐 kind 的一部分）、整节标题区块，最后是整篇文档。对齐只比较语言中立的 kind——标题深度、节点类型、容器归属——从不比较标题文字。
- 仅发生在逐字节一致围栏内的改动是机械的：`--apply` 把改过的围栏拼进对侧文件，并在写入前做结构校验（配对签名）。不涉及任何翻译判断。
- 每份简报按有改动的 span 打包：上次确认的源文、当前源文、当前对侧文本及对侧行号；另有被改一侧的 diff、其源语言术语出现在改动文本中的术语行、首次出现移动注记（「首次出现」括注跟随全文首次出现位置移动，因此把首现移出或移入的编辑会同时要求新旧两个 span 更新对侧），以及按方向区分的规则摘要。
- 双侧都漂移的配对始终按整篇工作出具简报：没有哪一侧是可信的映射锚点。
- 点名的配对在已同步、不完整或超出范围时报错退出；无参数时对每个失去同步的配对出简报。录制仍由 `hdsh pairing record` 承担。

消费简报的扩展工作流是 [`translating-docs`](../../../skills/translating-docs/SKILL.md)，仅限用户显式调用；日常更新保持 [docs/AGENTS.md](../../../../docs/AGENTS.md) 的直接一次通过路径。本仓库不存在自动翻译流水线，语料中也不携带任何机器消费的提示词模板。

## Alternatives considered

**总是整篇重译对侧。** 每次编辑都否定已评审的措辞并重开术语；记录 hash 的存在正是为了让最小 diff 可恢复。

**在树中为每个配对维护常驻简报文件。** 它会在编辑之间腐烂，并给配对的合并面增加第四个产物；简报是记录状态的渲染，可按需推导。

**从 git 历史而非一致性记录推导改动。** 记录的 blob hash 无需查历史即可指明确切的上次确认状态，且因录制先存快照而覆盖从未提交的 worktree 字节。

**由钩子或 CI 驱动简报。** 简报的存在是为了让显式请求的重型工作流变廉价；自动运行会重新制造本设计要去除的语料加载税。

**随库发布机器消费的提示词模板。** 其正文逐字改变流水线行为，而本仓库不运行此类流水线；配对化的模板只会是额外排除项后面的死重。

## Consequences

- 直接一次通过的规则仍是默认；简报是显式调用的加速器，技能语料新增 `disable-model-invocation: true` 的 `translating-docs`。
- 简报质量取决于记录状态：记录缺失或格式错误时报错退出，绝不猜测基线。
- 对齐天然保守——上次确认源文、当前源文与当前对侧之间的任何结构分歧都会升级到更宽的粒度，而不是错误映射 span；对 unit 与节都不可见的改动（例如行尾漂移）升级为整篇。
- span 语法与配对签名的解析器同处一个模块，unit kind 与门禁的结构比较不会无声漂移；测试以全分支覆盖锁定映射、机械拼接、首现跟踪与 CLI 面。
